# Правила формирования договоров — Энергосбыт

Это единственный источник правил для работы с объектами и договорами.
Действовать только по этому файлу. Если чего-то нет в файле, значит, правила на это нет.

## 1. Главные принципы

1.1. Задача: составлять договоры по материалам, которые приносят абоненты: проектам, фото счётчиков и фото пломб.
1.2. Действовать только по правилам этого файла. Ничего не додумывать и не принимать решений самостоятельно.
1.3. Если на ситуацию нет правила, остановиться и спросить пользователя, как поступить. Ничего не заполнять «по аналогии», «по смыслу» или «как обычно бывает».
1.4. Ответ пользователя записать в этот файл новым правилом (порядок описан в разделе 5) и только после этого продолжать работу.
1.5. Если значение нельзя прочитать однозначно (фото нечёткое, кадр обрезан, в разных документах разные данные), не угадывать, а спросить. (следует из 1.2)
1.6. Если два правила противоречат друг другу, не выбирать самому, а спросить. (следует из 1.2)

## 2. Хранение материалов

2.1. Материалы абонентов (проекты, фото), форма договора и готовые договоры хранятся только на компьютере пользователя. В git они не попадают. [2026-10-09]
2.2. В git хранятся только правила: `CLAUDE.md`, `energosbyt/rules.md`, `energosbyt/questions.md`, а также служебные файлы: `.gitignore` и пустые `.gitkeep`, благодаря которым папки появляются при клонировании. [2026-10-09]
2.3. Пользователь кладёт проекты и фото в папку `energosbyt/inbox/`.
2.4. Claude раскладывает материалы из `energosbyt/inbox/` по папкам объектов внутри `energosbyt/objects/`. [2026-10-09]
2.5. Название папки объекта содержит адрес объекта и дату поступления. Точный формат названия и то, какая дата считается датой поступления, пока не определены, см. `energosbyt/questions.md`. [2026-10-09]
2.6. Файлы переносятся как есть: их нельзя переименовывать, сжимать или редактировать. (следует из 1.2)
2.7. Папки `energosbyt/inbox/`, `energosbyt/objects/` и `energosbyt/template/` исключены из git через `.gitignore`. Не добавлять в git файлы из этих папок, не менять ради этого `.gitignore` и не использовать `git add -f`. (следует из 2.2) [2026-10-09]
2.8. Перед каждым коммитом проверить `git status`. В коммит могут попасть только файлы из п. 2.2. Если в списке есть что-то ещё, не коммитить и спросить пользователя. (следует из 2.2) [2026-10-09]

## 3. Составление договора

3.1. Договор составляется по материалам из папки объекта.
3.2. Типовая у договора только форма. Форма берётся из `energosbyt/template/`, поля заполняются по правилам раздела 4.
3.3. Каждое поле договора заполняется только по правилу из раздела 4. Если для поля правила нет, спросить (п. 1.3).
3.4. Если в `energosbyt/template/` нет формы, договор не составлять и сообщить об этом пользователю. (следует из 3.2)

## 4. Правила заполнения договора

Пока пусто. Раздел пополняется по ответам пользователя.

## 5. Как пополнять этот файл

5.1. Правила вносит Claude, и только со слов пользователя.
5.2. Новое правило ставится в подходящий раздел под следующим номером. Если подходящего раздела нет, создать новый.
5.3. В конце нового правила ставится дата добавления: [ГГГГ-ММ-ДД].
5.4. Внеся правило, показать пользователю его точный текст.
5.5. Менять и удалять правила можно только по прямому указанию пользователя. (следует из 1.2)
5.6. Вопрос, на который пока нет ответа, записывается в `energosbyt/questions.md`. Когда ответ получен, правило вносится в этот файл, а вопрос удаляется из `energosbyt/questions.md`.
5.7. Каждое изменение этого файла оформляется отдельным коммитом и отправляется (push) в репозиторий. [2026-10-09]
