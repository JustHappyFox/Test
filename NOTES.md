Карточку «Розыгрыш призов… Участники… Дата окончания» рисует приложение из этих полей; при копировании даёт ссылку, т.к. текста нет. Проверено на t.me/Z_2_Z/45719. ## Исследование API Telegram (05.11, по просьбе владельца «нужен свой API»)
- Мы уже работаем через внутренний API Telegram (MTProto, слой 229 — тот же, что у официальных приложений: 823 метода, 1697 типов).
- Аналогия с «неофициальным API Яндекс Музыки» не работает: там повторяют возможности приложения, а приложения Telegram сами не умеют искать розыгрыши глобально — скрытой функции нет.
- Методы про розыгрыши: `payments.getGiveawayInfo` (по известному посту), бусты (`premium.getBoostsStatus/List` — только для админов своего канала), подарочные коды, запуск своего розыгрыша. Поиска среди них нет.
- Фильтров поиска сообщений 18 (фото, видео, ссылки, опросы…), фильтра «розыгрыш» нет. Глобальные поиски (`messages.searchGlobal`, `channels.searchPosts`, `contacts.search`) — только по тексту/названиям.
- Telegram Web (исходники `morethanwords/tweb`, `Ajaxy/telegram-tt`) — тот же клиент на том же API (MTProto через WebSocket, как наш бот из облака), своей базы нет. Про розыгрыши он вызывает только `payments.getGiveawayInfo` (клик по розыгрышу в открытом чате) и методы запуска своего розыгрыша; розыгрыши видит лишь как сообщения в открытых чатах.
- Готовые базы розыгрышей есть только у сторонних: telegramgiveaways.ru (= канал @giveaways_database, уже наш источник №1), TGStat/Telemetr (платные API).
- Идея владельца «соединить поиск Telegram с меткой» **проверена 05.11**: поиск по 11 хэштегам нашёл текстовые посты про розыгрыши в 1968 каналах; в 250 из них проверены соседние сообщения (±4 от каждого поста) — **0** официальных розыгрышей по метке. Хэштеги/текст ведут к обычным конкурсам, официальные розыгрыши публикуют отдельно, без текста. Скрипт: `scratchpad/search_neighbors.py`.
- Вывод: «свой API» = **собственный индекс розыгрышей** (как TGStat): растущий реестр каналов + почасовой инкрементальный обход (только новые посты, 1 запрос на канал) + база розыгрышей + выдача из базы. Предложено владельцу, ждём «начинаю».

## Как устроено (GitHub)
- **Агрегаторы проверяются минимум раз в сутки** (06.11 владелец: «раз в день надо проверять их»): `--daily-search-hours 24` — если поиска не было 24 ч, поиск идёт даже при непустом запасе (до 10).
