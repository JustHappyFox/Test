# Инструкция: пакет документов юр лица («БС - юр лицо» в «Договоре») по бумагам пользователя

> Записано 24.11 по первому реальному пакету (зарядные станции электромобилей, учёт с трансформаторами тока).
> ДАННЫЕ ИЗ БУМАГ - ТОЛЬКО В SCRATCHPAD. В git, журналы и коммиты - ни названий юр лиц, ни адресов, ни номеров, ни фамилий.

## Что на выходе (пользователь просит: «архивом готовые документы и шаблон заполненный, и фотки»)
1. Архив (имена файлов cp866 - `razrabotka/tools/zip866.py`, иначе Windows 7 покажет «кракозябры»), распаковывается в папку
   «Оформление договора» с заменой:
   - `БС/<пакет>/` - 5 документов (справка для производства расчетов, акт приемки приборов учета, доп. соглашение, наряд,
     потери (Приложение 8)) + `Схема питания.jpg`;
   - `БС/данные/<пакет>.txt` - сохранённая форма («Открыть сохранённый…»); строку `shema=` заменить на `shema=Схема питания.jpg`
     (программа сама найдёт схему в папке пакета);
   - `ПРОЧТИ.txt` - что взято из бумаг, что дописать руками, что проверить.
2. Снимки: заполненная форма по разделам (скриншоты под Xvfb) и страницы документов (docx -> PDF -> PNG, `pdftoppm -r 90`).
3. После правок программы - ещё и `programmy.zip` (проект целиком, `pack.py all`).

## Как делать
1. Копия программы для работы: `mkdir scratchpad/ev/prog && cp dogovor/*.docx scratchpad/ev/prog/` (справочник и настройки
   программа создаст сама; в папку `dogovor/` репозитория ничего не генерировать, а если появилось - удалить).
2. Заготовка сценария - `razrabotka/tests/bs_paket_fill.cs` (вымышленные данные). Скопировать в scratchpad, вписать данные из
   бумаг, запустить: `T_SHEMA=схема.jpg runtest.sh dogovor <сценарий> <scratchpad/ev/prog> <png-префикс> 40`. Сценарий
   заполняет форму, снимает каждый раздел и формирует пакет (`b.Save(false,false)`), печатает собранные строки и «Не заполнено».
   Порядок важен: «Другие пломбы» (`plomba_drugoe`) ставить ДО `plomba_klemm`, иначе строка пломб в акте не соберётся.
3. Проверить документы (и что НИЧЕГО не выходит за поля листа - распечатку обрезает: таблицы шире текста ужимает tpl_fix.py): `soffice --headless --convert-to pdf`, посмотреть каждую страницу; `pdftotext ... | grep` - подписи,
   даты, точка учёта. Схема: фото повернуть (`convert -auto-orient -rotate -90`), вырезать рамку схемы, `-colorspace Gray -level 30%,78%`.

## Откуда что брать (бумаги юр лица) -> поле формы
| Бумага | Что из неё |
|---|---|
| Письмо «о внесении в договор» | № и дата договора (`dog_nom`, `dog_data`), наименование объекта, телефон контактного лица (`tel`) |
| Свидетельство о регистрации / «Сведения» (категория, тарифная группа) | наименование юр лица (`abonent`: «ООО «...»»), тарифная группа (`tarif`), мощность |
| Приложение 1 (договорная величина) | объём - в документы пакета не идёт |
| Технические условия | мощность, категория, источник питания; разрешённая мощность (`moshn`) |
| Акт разграничения балансовой принадлежности | дата (`data_razgr`), питание от (`pitanie`, напр. КТПБ-№), линия (`liniya`: «КЛ-0,4 кВ: КТПБ-№ - ЩУ... марка L=..м.»), схема питания (`shema` - фото схемы из акта) |
| Проект (схема электрическая принципиальная, ведомость) | место включения для наряда (`mesto`: «КТПБ-№, РУ-0,4 кВ, 2 секция, руб. 14»), кабель и длина для потерь (`linii`: «0,4\|АВБбШв-4х95\|0,044\|\|» - r0 и Rл считаются сами по справочнику [БС: кабель и r0]), тип счётчика и ТТ |
| Акт осмотра (допуска) энергогазинспекции | подтверждает описание электроустановки, мощность, категорию |
| **Акт приемки/опломбировки средств расчетного учета** (выезжал инженер) | счётчик: тип, №, ток, класс, поверка (квартал и год); показания (если «без напряжения» - так и писать); ТТ: тип, номера фаз A/B/C, 150/5 -> коэффициент; пломбы МЭСБ по местам; сельсовет (в адресе акта); **ДАТА ПАКЕТА = дата этого акта** |

## Поля, о которых надо помнить
- **Точка учёта** (`pu` столбец 1 и `moshn` столбец 1): как скажет пользователь (для зарядных станций - **ЭЗС**, для БС - ЩУЭ / ЩУНИ).
- **Учёт с трансформаторами тока**: строка ПУ `точка|тип|№|3х230/400|5(10)|показания|кв|год|ТТ тока|ТТ напр.|К расч`;
  «ТТ тока» - «ТОП-0,66... 150/5 кл.т. 0,5S № A, B, C (пов. год кв.)», «ТТ напр.» - «-», «К расч» - 150/5 = 30.
  Прямое включение: ТТ «-», К = 1.
- **Пломбы**: маркировка МЭСБ; клеммная крышка счётчика - `plomba_klemm`; остальные - `plomba_drugoe` строкой
  «ИК 1; ТТ 2, 3, 4; ФП 5» (места из справочника [Места пломб]: ИК, ТТ, ФП, ДСТП, КК, ВА). В акт - «Клемная крышка ... опломбирована
  пломбой ...»; при сохранении пакета пломбы идут в отчёт пломб.
- **Даты**: `data_pu`, `data_podp`, `data_akt` - дата акта опломбировки (не сегодняшняя!), если пользователь не сказал иначе.
- **Подписи**: `nach_dolzh` (Начальник ГРП / Начальник ОПСУ - спросить или как сказал пользователь), `nach`; инженер `inzh`
  (Фамилия И.О.) и `inzh_fio` - полностью для акта приемки (полное имя - со слов пользователя; посоветовать дописать в справочник
  [БС: инженер] «Фамилия И.О. = Фамилия Имя Отчество»). В репозиторий фамилии не писать.
- **Объект**: `obekt` - наименование как в бумагах без адреса; `kod` (вид сооружения и код) - пусто, если в бумагах нет (для БС -
  «сооружение специализированное связи, код 3 07 00»); `deyat` - характер деятельности для акта приемки, п. 4
  («...используется для зарядки электромобилей» / «...для электроснабжения базовой станции»).
- **Адрес**: область «Минская обл.», район «Минский р-н», сельсовет (из акта опломбировки, если есть), тип н.п., н.п., улица, дом.
  Строки адреса и объекта собираются сами.
- **Наряд**: `vid` включение, `prichina` «Допуск в эксплуатацию», `mesto`; номер и дата наряда остаются пустыми (впишут).
- **Доп. соглашение**: пункт 1 и тарифная группа - из справочника; ТРЭТ и примечание «-».

## Потери (Приложение 8) - по ТКП 460-2017
Перед «потерями» читать `razrabotka/POTERI.md`: по акту разграничения определить, что лежит между ГБП и счётчиком (кабель/ВЛ,
силовой трансформатор, ТТ, ТН), чей это участок (знак поправки), d по режиму работы, r0 по таблицам Б. Шаблон сейчас умеет
только случай «линия 0,4 кВ абонента»; трансформатор, ТТ (+4,2 кВт·ч/мес на 0,38 кВ), ТН - пока дописать в Word и сказать
пользователю.

## Чего обычно нет в бумагах - перечислить пользователю в ПРОЧТИ.txt и в ответе
№ счётчика / показания / поверка (если нет акта опломбировки), номера ТТ, пломбы, сельсовет, полное имя инженера, номер наряда.
Ничего не выдумывать: неизвестное - пусто и в список «допишите»; взятое по смыслу (r0 кабеля, место включения со схемы) - в «проверьте».
