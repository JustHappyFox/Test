# tg_giveaway_finder

Скрипт ищет в Telegram **ещё не завершённые официальные розыгрыши** (Telegram Premium и Stars), то есть те, что запущены через встроенный механизм Giveaways, а не через сторонних ботов.

Такой розыгрыш в API Telegram — это сообщение с медиа [`messageMediaGiveaway`](https://core.telegram.org/constructor/messageMediaGiveaway). В нём записаны каналы-участники, число победителей, дата окончания и приз. Скрипт ищет именно такие сообщения, поэтому обычные посты «конкурс, жми кнопку» в выдачу не попадают.

## Где он ищет

**Не только в ваших подписках.** Обычный `scan` вообще не смотрит, на что вы подписаны. Он сам находит **публичные** каналы и группы через поиск, а читать публичные каналы Telegram позволяет без подписки. Ваши подписки добавляются только флагом `--dialogs`.

Ограничения:
* **Закрытые** каналы и группы без подписки прочитать нельзя. Если такой канал окажется спонсором розыгрыша, он будет указан в списке каналов, но сам по себе просмотрен не будет.
* Режим `watch` видит **только ваши чаты**: Telegram присылает новые сообщения в реальном времени только из них.

## Важно: «весь Telegram» обойти нельзя

В Telegram нет метода «покажи все активные розыгрыши». Поиск сообщений по типу медиа тоже работает только в пределах одного чата. Поэтому скрипт собирает охват из нескольких источников:

| Источник | Как работает | Флаг |
|---|---|---|
| Ваши каналы и группы | читает всё, на что вы подписаны, включая пересланные розыгрыши | `--dialogs` |
| Каналы-агрегаторы | встроенный список публичных каналов, куда пересылают официальные розыгрыши (`@giveaways`, `@Giveaways_Premium_Tel`, `@TgPremiumGiveaway`, `@tgpremium_giveaways`, `@ChannelGiveaways`) | включено по умолчанию, `--no-aggregators` |
| Свой список каналов | например, каналы-агрегаторы, куда пересылают розыгрыши | `-c`, `--channels-file` |
| Поиск по названию | `contacts.search` по словам «розыгрыш», «giveaway», «premium», «звёзды»… | включено по умолчанию |
| Поиск по хэштегам | `channels.searchPosts` по публичным постам `#розыгрыш`, `#giveaway`… | включено по умолчанию |
| Полнотекстовый поиск постов | `channels.searchPosts(query=…)`, только в пределах **бесплатного** дневного лимита, Stars не тратятся | `--post-search "..."` |
| Снежный ком | каналы-участники найденных розыгрышей и источники пересылок добавляются в очередь, а у таких каналов часто бывают и другие розыгрыши | `--depth` (по умолчанию 2) |

Каждый канал скрипт читает за последние `--days` дней (по умолчанию 31) и берёт розыгрыши с `until_date` в будущем. Одинаковые розыгрыши склеиваются: один и тот же розыгрыш публикуется во всех каналах-спонсорах и пересылается агрегаторами.

С флагом `--check` скрипт для каждого розыгрыша вызывает `payments.getGiveawayInfo` и показывает, можете ли участвовать **именно вы**: участвуете ли уже, не ограничена ли страна, не стоит ли «только новые подписчики» при давней подписке, не админ ли вы. Розыгрыши, по которым уже подведены итоги, при этом отбрасываются.

## Запуск без установки — в облаке (Google Colab)

Ставить ничего не нужно: скрипт выполняется на серверах Google, нужен только браузер (подойдёт и телефон).

1. Откройте <https://colab.research.google.com>, затем **Файл → Открыть блокнот → GitHub**.
2. Введите `JustHappyFox/Test`, выберите ветку `claude/telegram-giveaway-finder-mhm9ut` и откройте `giveaway_finder_colab.ipynb`.
   После слияния в `main` блокнот откроется сразу по ссылке: <https://colab.research.google.com/github/JustHappyFox/Test/blob/main/giveaway_finder_colab.ipynb>.
3. Нажимайте ▶ у ячеек по очереди. Блокнот спросит `api_id`/`api_hash` (их можно заранее сохранить в 🔑 «Секреты» Colab), номер телефона и код из Telegram, а в конце покажет таблицу с кликабельными ссылками и предложит скачать CSV.

Код входа и сессия остаются в вашем аккаунте Google, третьим лицам они не передаются. Чтобы не вводить код при каждом запуске, сохраните строку сессии в «Секреты» под именем `TG_STRING_SESSION` (последняя ячейка блокнота). Режим `watch` в Colab не подходит: машина отключается, если на ней ничего не происходит.

## Если наружу пускают только HTTPS (облачные среды, корпоративные сети)

Обычно скрипт подключается к Telegram напрямую по TCP. Если прямые подключения закрыты и выход есть только через HTTPS-прокси, он подключается так же, как Telegram Web: по WebSocket к `wss://<dc>.web.telegram.org/apiws`. Протокол внутри тот же (MTProto), меняется только канал связи.

* Включается сам, если задана переменная `HTTPS_PROXY`. Принудительно: `TG_TRANSPORT=ws` или `TG_TRANSPORT=tcp`.
* Нужен пакет `aiohttp` (есть в `requirements.txt`).
* В списке разрешённых доменов должны быть `venus.web.telegram.org`, `pluto.web.telegram.org`, `aurora.web.telegram.org`, `vesta.web.telegram.org` и `flora.web.telegram.org`.

## Установка на свой компьютер

Нужен Python 3.10 или новее и **пользовательский** аккаунт Telegram: бот не может читать чужие каналы.

```bash
git clone <этот репозиторий> && cd Test
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env    # и впишите TG_API_ID / TG_API_HASH
```

`TG_API_ID` и `TG_API_HASH` выдаются на <https://my.telegram.org> в разделе **API development tools**. Это бесплатно и занимает минуту.

При первом запуске скрипт спросит номер телефона, код из Telegram и, если включён, пароль 2FA. После этого рядом появится файл `giveaway_finder.session`.

> ⚠️ Файл `*.session` даёт **полный доступ к аккаунту**. Никому его не передавайте и не коммитьте (он уже есть в `.gitignore`).

## Использование

```bash
# Простой запуск: сам ищет публичные каналы с розыгрышами (подписки не нужны)
python tg_giveaway_finder.py scan --check

# То же + ваши подписки, в осторожном режиме (пауза 30 с после каждых 500 каналов)
python tg_giveaway_finder.py scan --dialogs --check --careful

# Только розыгрыши Stars, без тех, где участвовать нельзя, с сохранением в CSV (открывается в Excel)
python tg_giveaway_finder.py scan --dialogs --check --prize stars --hide-ineligible --csv giveaways.csv

# Свой список каналов-агрегаторов, без автопоиска
python tg_giveaway_finder.py scan --channels-file channels.txt --no-discover

# Шире: больше каналов, свои слова и хэштеги, плюс полнотекстовый поиск постов
python tg_giveaway_finder.py scan --max-channels 800 --keywords "розыгрыш тг премиум" "stars раздача" \
    --hashtags розыгрыш giveaway премиум --post-search "розыгрыш premium"

# Копить найденные каналы между запусками, чтобы с каждым разом охват рос
python tg_giveaway_finder.py scan --dialogs --save-sources channels.txt
python tg_giveaway_finder.py scan --channels-file channels.txt --save-sources channels.txt

# Режим наблюдения: сообщать о новых розыгрышах в ваших чатах сразу, как они появились,
# и пересылать их в «Избранное»
python tg_giveaway_finder.py watch --notify
```

Пример вывода:

```
[1] 5000 ⭐ Stars, победителей: 10 (~500 ⭐ каждому)
    До: 2026-11-06 18:00 (осталось 2д 1ч)
    Каналы (2): Some Channel (@some_channel) ✅, Sponsor (@sponsor) ➕
    Условия: только новые подписчики; страны: RU, KZ
    Статус: ➕ можно участвовать — подпишитесь на все каналы
    Ссылка: https://t.me/some_channel/1234
```

✅ означает, что вы уже подписаны, ➕ — что нужно подписаться. В официальном розыгрыше участвуют подписчики **всех** перечисленных каналов, а если стоит «только новые подписчики», то только те, кто подписался после старта.

Все опции: `python tg_giveaway_finder.py scan --help`.

**Вход на сервере или в облаке, где нельзя ввести код в окне программы,** делается по шагам:

```bash
python tg_giveaway_finder.py login --phone +79991234567     # Telegram пришлёт код в приложение
python tg_giveaway_finder.py login --code 12345
TG_2FA_PASSWORD='...' python tg_giveaway_finder.py login --password   # только если включена 2FA
python tg_giveaway_finder.py logout    # завершить сессию (пропадёт из «Настройки → Устройства»)
```

## Автопостинг в канал раз в 3,5 часа (GitHub Actions)

Задание [`.github/workflows/repost.yml`](.github/workflows/repost.yml) раз в 3,5 часа ищет активные официальные розыгрыши и пересылает **один новый** в канал @TGaGifts.

Запуски по расписанию GitHub приходят нерегулярно, а иногда пропадают на несколько часов подряд. Поэтому бот ставит посты в канал как **отложенные** (`--schedule-ahead 2`): в канале всегда есть 2 следующих поста с шагом 3,5 часа, и публикует их сам Telegram точно по времени. Запуски каждые полчаса только поддерживают этот запас. Отложенные посты видны админам в канале (меню «Отложенные сообщения»), их можно передвинуть или удалить вручную, бот это учтёт.

* **Что подходит:** Stars от 10 000 звёзд и Premium от 5 подписок; только «для всех стран», РФ, РБ и КЗ. Розыгрыши «для всех стран» идут первыми.
* **Откуда пересылается:** из **канала-организатора**, даже если розыгрыш найден через агрегатор.
* **Что не пересылается:** завершённые розыгрыши и те, до конца которых меньше 3 часов.
* **Без повторов:** что уже переслано, запоминается в кэше GitHub Actions. Начальное состояние лежит в `state/`.
* **Ваши ручные посты:** перед каждой публикацией бот читает последние посты канала. Если вы сами что-то опубликовали (любой пост, кроме служебных сообщений вроде «закреплено»), следующий пост бота выйдет не раньше чем через 5 часов после вашего (`--manual-gap-hours 5`). Розыгрыши, которые уже есть в канале, бот не дублирует, кто бы их ни опубликовал.
* **Очередь вместо лишних поисков:** найденные, но ещё не опубликованные розыгрыши хранятся в очереди. Когда подходит время поста, скрипт сначала берёт розыгрыш из очереди: это одна пересылка за пару секунд. Сканирование запускается, только если очередь опустела. Пополнить очередь вручную: `post --refill`.
* **Ручной запуск:** вкладка **Actions** → «Репост розыгрышей в @TGaGifts» → **Run workflow**.

Аккаунт, от имени которого идёт пересылка, должен быть админом канала с правом публиковать сообщения. В репозитории нужны секреты (**Settings → Secrets and variables → Actions → New repository secret**):

| Секрет | Значение |
|---|---|
| `TG_API_ID` | api_id с my.telegram.org |
| `TG_API_HASH` | api_hash с my.telegram.org |
| `TG_STRING_SESSION` | строка сессии аккаунта (полный доступ к аккаунту, держите в секрете) |

Для публичного репозитория минуты GitHub Actions бесплатны. GitHub отключает задания по расписанию, если в репозитории 60 дней не было коммитов. Чтобы этого не случилось, задание [`keepalive.yml`](.github/workflows/keepalive.yml) раз в 55 дней делает служебный коммит: добавляет или убирает одну букву в `.github/keepalive`. Если завершить сессию в Telegram (**Настройки → Устройства**), автопостинг остановится: нужна будет новая строка сессии.

## Как получить больше розыгрышей

* **Подпишитесь на 2–3 канала-агрегатора**, которые пересылают официальные розыгрыши, и запускайте `scan --dialogs` или держите включённым `watch --notify`. Это самый надёжный источник. Скрипт понимает пересылки и ведёт на оригинальный пост. Готовых проверенных названий таких каналов я не нашёл, ищите в TGStat или в Telegram по словам «розыгрыши premium».
* Используйте `--save-sources`: каждый запуск пополняет список каналов, где уже бывали розыгрыши.
* Увеличьте `--max-channels` и `--depth`, но не забывайте про лимиты (см. ниже).

## Лимиты и безопасность аккаунта

* **Осторожный режим `--careful`.** Пауза 30 с после каждых 500 каналов, между отдельными каналами пауз нет. Если Telegram просит подождать (FloodWait) до 5 минут, скрипт ждёт и продолжает, а не обрывает обход. Пачку и паузу можно поменять: `--batch-size 300 --batch-pause 60`. Пауза между отдельными каналами задаётся через `--delay 1-3` (по умолчанию её нет).
* Telegram ограничивает частоту запросов (FloodWait). Короткие ожидания скрипт пережидает сам (`--max-flood-wait`, по умолчанию 120 с). Если лимит длиннее, он останавливает обход и показывает то, что успел найти. Ctrl+C тоже выводит частичный результат.
* Скрипт **только читает**. Он не подписывается на каналы и ничего не публикует (кроме `watch --notify`, который пишет вам в «Избранное»). Автоподписок в нём нет специально.
* Массовые автоподписки ради розыгрышей — частая причина ограничений аккаунта. Telegram также [отзывает призы, полученные «нечестно»](https://www.iguides.ru/main/other/telegram_nakonets_to_poborol_botov_khalyavshchikov_bolshe_nikakikh_besplatnykh_premiumov/). Для экспериментов лучше завести второй аккаунт.
* Не вводите код входа и не загружайте `.session` на сторонние сайты и в боты «бесплатного премиума».

## Что нашлось готового (для сравнения)

Полноценного «поисковика розыгрышей по всему Telegram» на GitHub я не нашёл. Похожие проекты закрывают только часть задачи (я смотрел фрагменты кода через поиск GitHub, а не полный аудит):

* [FajoX1/FAmods — `giveaways.py`](https://github.com/FajoX1/FAmods) и [yummy1gay/modules — `yg_prem.py`](https://github.com/yummy1gay/modules): модули для юзерботов Hikka/Heroku, которые ловят новые `MessageMediaGiveaway` в ваших чатах. По сути это аналог `watch`, но без поиска новых каналов.
* [leviAnet/auto-join-telegram-giveaway](https://github.com/leviAnet/auto-join-telegram-giveaway): скрипт автоучастия в розыгрышах Stars и Premium.
* [tlgrcli/tlgr](https://github.com/tlgrcli/tlgr): CLI для Telegram с командами `giveaway` (информация о розыгрыше, участие, подарочные коды).
* ⚠️ Встречаются репозитории вроде «Telegram Gift Parser / auto-giveaway-grabber», у которых README — набор SEO-ключевиков. Через такие часто распространяют стилеры сессий, я бы их не запускал.

Документация API: [Giveaways](https://core.telegram.org/api/giveaways), [messageMediaGiveaway](https://core.telegram.org/constructor/messageMediaGiveaway), [Star giveaways (блог Telegram)](https://telegram.org/blog/star-giveaways-iv-in-browser/ru).
